# 日常 DAILY

每天，和世界见一面。中文资讯小站第一版，电脑和手机均可使用。

## 运行

需要 Node.js 22 或更新版本。首次安装两项正文解析依赖，然后启动：

```sh
npm ci
npm start
```

浏览器访问 http://127.0.0.1:4173 。`npm run check` 检查 JavaScript 语法，`npm test` 运行正文解析、NBA 筛选和 HTTP 路由测试。

## 第一版功能

- 输入名字进入，显示「欢迎！xxx」；可勾选「30天内记住我的用户名」。
- 今日精选、科技前沿、看见世界、生活方式、人文与艺术、商业观察、NBA 专栏、人像卡；栏目导航分别使用相关照片，保留毛玻璃底板与明显选中状态。
- 人像卡面向工牌、校牌、胸牌和徽章制作，包含行业动态、制作流程与实用技巧。6 篇中文工作指南由本站整理，参考资料在文末标明，支持站内阅读、分享、刷新与收藏。
- 实时公开新闻源、新闻来源和真实发布时间、站内文章阅读。
- 所有资讯卡片显示真实照片；优先来源原图，缺失时显示标明“栏目配图”的本地照片。
- 站内文章页保留正文、图片、来源、收藏与相关阅读；支持直接打开文章链接、刷新与浏览器返回。正文获取失败时明确显示来源摘要。
- 栏目筛选、搜索、收藏、分页、手动刷新与自动更新。
- 各名字在当前浏览器拥有独立收藏夹；支持切换名字和退出。
- 手机和桌面适配、键盘操作、加载及网络异常状态。

## 信息来源

中国新闻网公开 RSS（滚动、国际、财经、文化、生活、社会），IT之家公开 RSS，以及央视网 NBA 公开资讯流。服务器并行获取，7 分钟缓存、8 秒连接超时、URL 去重。失联时暂存最多 24 小时旧缓存并标记；不生成虚构新闻。发布时间来自原始 RSS，个别栏目最新文章可能早于当天。

人像卡行业动态读取 Evolis 官方博客列表（其 RSS 已停用），过滤无关内容。6 篇已核实文章附中文标题和导读，正文保留来源原文；未知日期不补写。博客失联且无有效缓存时显示明确标注的 3 篇官方文章选读，保留原发布日期。实用指南参考 Evolis 证卡技术资料与卓泰克胸牌制作教程，和行业消息分区展示，不冒充当天新闻。

「今日精选」按发布时间排序；「新鲜事速览」从不同栏目取近期文章，没有虚构热度排名。来源图片不可访问时显示本地栏目照片，并标注“栏目配图”。栏目照片的作者及许可见 `/images/credits.html`。

文章接口只读取已接入发布方的正文，以结构化文本渲染；不会嵌入原站页面、脚本或广告。照片代理有来源限制和大小、时间上限。站内阅读页路径为 `/article/<id>?url=<原发布地址>`，保留来源参数可在新闻移出列表后继续尝试读取。

## 名字和收藏

勾选「30天内记住我的用户名」后，名字和固定到期时间保存在当前浏览器 localStorage 中，30 天后重新输入，访问不会自动续期；默认不勾选，名字仅保存在当前标签页的 sessionStorage 中。退出登录会清除两种名字记录。旧版保存的名字会转为本次会话，需自行勾选才会记住 30 天。

各名字的收藏仍保存在当前浏览器 localStorage 中，退出登录或到期不会删除收藏。名字和收藏不上传服务器，不需要密码。同名并不等于验证身份，也不能跨设备同步。清除浏览器数据会删除该浏览器的记录。

## 发布到固定网址

网站需要部署到托管平台才能供其他人独立访问，`127.0.0.1` 只供本机使用。已准备 GitHub Pages 免费静态发布方案；是否上线以仓库 Pages 设置和实际网址检查为准。

### GitHub Pages 免费方案

使用公开仓库、GitHub Pages 和标准 GitHub Actions runner，不需要租服务器、购买域名或配置新闻 API 密钥。在仓库 Settings → Pages → Build and deployment 中将 Source 设为 GitHub Actions。默认分支使用 `main`，推送代码会触发 `.github/workflows/pages.yml`，也可在 Actions 页面手动运行。工作流会自动使用项目的 Pages 路径；网站地址一般为 `https://<用户名>.github.io/<仓库名>/`。

Pages 只发布静态文件。Actions 每小时第 23 分钟计划获取来源新闻、正文与封面照片，并生成整站。定时运行可能延迟或漏跑；公开仓库 60 天无活动时，GitHub 会自动停用定时任务，需要在 Actions 中重新启用。一次抓取完全失败时构建失败，上一版已发布网站保持可用。

```sh
npm ci
npm run build:pages -- --out-dir dist --base-path /daily-news/
```

生成的 `dist/` 包含浏览器文件、`data/news.json`、每篇站内文章 JSON 与本地照片。文章链接使用 `?article=<id>`，支持项目目录、直接打开和刷新。按钮“刷新”重新读取最近一次发布内容，不会现场抓取新闻。名字和收藏仍只保存在访问者的浏览器中。

每版最多 300 篇当前资讯；封面图片最多下载 60 MiB，每张最大 5 MiB，失败时使用标有“栏目配图”的照片。正文保留真实来源文本及时间；当前静态版每篇显示一张封面，正文插图原始地址保存在 `provenance.sourceImages`，不逐张发布。无法获取正文时明确展示来源摘要。过期文章若仍在此浏览器的收藏中，会显示实际已保存的内容或摘要；其他旧分享链接不提供永久归档保证。

`--previous-dir <目录>` 可供本地导出读取 48 小时内的有效旧快照；默认工作流不依赖旧构建缓存。发布产物仅保留一天，不累积长期 Actions 存储。免费服务的用量限制及访问表现以 GitHub 当前政策和实际访问为准。

### 其他已准备的运行方式

**Vercel**：已提供 `vercel.json` 和 `api/` 无状态函数。账号验证完成后，在项目目录执行 `npm run deploy`，按提示创建项目，平台可分配 `*.vercel.app` 网址，无需先购买域名或数据库。

**Netlify 备用配置**：已提供 `netlify.toml` 和 `netlify/functions/`，复用同一组新闻、文章、图片和健康检查接口。托管账号登录并能访问平台后，在项目目录运行 `npx netlify-cli login`，然后 `npx netlify-cli deploy --build --prod`，按提示创建或选择站点。发布目录是 `public`；不要仅拖拽这个文件夹到 Netlify Drop，否则后端接口不会发布。CLI 构建会按配置一并打包 Node22 函数、依赖和本地 JPG。Netlify 的站点地址通常为 `*.netlify.app`，最终地址及免费额度以实际账号页面为准。

Netlify 使用 Lambda 兼容入口，保留 query 参数、GET/HEAD 行为、错误状态以及二进制图片的 base64 响应；`zisi` 打包保留后端模块相对路径，使栏目 JPG 回退路径有效。`/api/*` 重写到对应函数，`/article/:id` 重写到本站阅读页，直接分享文章和刷新均有路由配置。安全响应头沿用本机/Vercel。函数单测可执行 `node --test tests/netlify.test.mjs`。

发布会上传 `public`、相关后端函数、依赖清单和配置；浏览器内的名字与收藏不会上传。平台免费计划、函数额度和访问表现必须在部署后核实。

这是普通 Node HTTP 服务，可部署到支持 Node 22+ 或 Docker 的主机。无需数据库或 API 密钥。

- 启动命令：`npm start`
- 环境变量：`HOST=0.0.0.0`、平台提供的 `PORT`（默认 4173）。
- 健康检查：`/api/health`
- 新闻接口：`/api/news`，支持 `category=hot|tech|world|life|culture|business|nba` 和 `refresh=1`。
- 文章接口：`/api/article?id=<16位编号>&url=<原发布地址>`。
- 封面图片：`/api/image?id=<16位编号>&url=<原发布地址>&category=<栏目>`，返回 `X-Image-Kind: article|category`。
- Docker：`docker build -t daily-web .`，然后 `docker run -p 4173:4173 daily-web`。
- 云服务器已安装 Docker Compose 时，可在项目目录运行 `docker compose up -d --build`；提供的 `compose.yaml` 将服务映射到 80 端口并配置自动重启与健康检查。云防火墙仍需允许 Web 端口；HTTPS 需在选定域名后配置。当前机器未安装 Docker，Compose 尚未在实际服务器上运行验证。
- 服务器需要能访问中国新闻网、IT之家、央视网和 Evolis 官方 HTTPS 来源。
- 生产环境推荐配置 HTTPS，并由运行平台管理进程重启。

临时隧道仅用于短期预览，依赖本机服务与隧道持续运行；服务商可能有时长限制。长期分享需要部署到托管平台或用户的服务器并取得固定域名。
